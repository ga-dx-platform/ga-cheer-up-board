## Anti-Patterns Verdict

**LLM assessment**: The interface reads as designed, not generated. The live card preview, progressive disclosure form architecture, aurora-glassmorphism aesthetic, and warm bilingual copy are deliberate choices that would not appear in a default AI scaffold. The single remaining tell is single-font typography.

**Deterministic scan**: Two findings.
- `single-font` (warning): Kanit still the only family. True finding.
- `em-dash-overuse` (5 instances, down from 6): Near-false positive. Four are stat loading placeholders. One is the card-sender attribution dash. True title/copy em-dashes resolved this session.

## Overall Impression

30/40, well-earned. Largest remaining opportunity: typography — a second font face at display scale would lift perceived craft from "well-executed single-font" to "considered design system." Everything functional is working well; this is now a polish and personality question.

## What's Working

1. **The stat skeleton.** Opacity-pulse animation with prefers-reduced-motion alternative signals "loading" rather than "broken." Done correctly.

2. **Welcome modal coverage.** Four features covering every non-obvious interaction (post, react, comment, anonymous), combined with persistent re-openable btn-about. Genuinely excellent contextual onboarding for this product's scope.

3. **Anon UX cohesion.** tabIndex=-1 keyboard fix, CSS dimming, inline confirmation hint, and localStorage persistence together form one designed feature.

## Priority Issues

### [P2] Single font — heading personality gap

**What**: Kanit is the only typeface. letter-spacing: -0.02em on headings creates a small display register shift but not genuine typographic contrast.

**Why it matters**: "Warm, Playful, Encouraging" calls for a typeface with personality at display size. Kanit handles everything from captions to hero headings with no moment where type does expressive work.

**Fix option A**: Load Kanit 800 for hero title only with letter-spacing: -0.035em at display size.
**Fix option B**: Pair Kanit with a rounded display face (Nunito 800, Mitr 700, Prompt 700) for headings only.

**Suggested command**: /impeccable typeset

---

### [P3] Preview sender attribution dash

**What**: Cards and the submit modal preview show "— sender" format. Detector flags this as part of em-dash count. The em-dash attribution prefix is a valid convention but reads as a minus sign to non-typography-fluent readers.

**Fix**: Remove the dash and distinguish the sender name via muted color/weight alone. Or use an en-dash which is semantically correct for attribution and won't trigger the detector.

**Suggested command**: /impeccable clarify

---

### [P3] Advanced fields discovery gap

**What**: The "ปรับแต่งเพิ่มเติม" toggle hides emoji, recipient, and image upload with no hint of what's inside. Users wanting to tag a colleague won't know the recipient field exists.

**Fix**: Add a subtitle to the toggle: "อีโมจิ · ส่งถึงใคร · แนบรูป" — one line makes the entire feature set discoverable without expanding.

**Suggested command**: /impeccable clarify

---

### [P3] No edit or delete for own posts

**What**: Once submitted, posts cannot be modified or removed by the author.

**Fix**: A 5-minute grace period delete via localStorage token matching would cover most cases without user accounts.

**Suggested command**: /impeccable craft (future feature)
